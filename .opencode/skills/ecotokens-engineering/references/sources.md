# Ecotokens Engineering Sources

Read only the section matching the current task. These are references, not executable skills.

## UI, Design, Motion, and 3D

Primary:

- `https://github.com/mui/material-ui` - accessible React components, theming, and design-system patterns.
- `https://github.com/mrdoob/three.js` - authoritative Three.js implementation and examples.
- `https://github.com/pmndrs/react-spring` - spring-based React interaction and animation patterns.
- `https://github.com/airbnb/lottie-web` - Lottie renderer and web animation integration.
- `https://github.com/tweenjs/tween.js` - framework-independent tweening and easing.

Discovery and visual references:

- `https://github.com/itmeo/webgradients` - gradient palette examples.
- `https://github.com/Gradients/awesome-gradient` - inactive but useful gradient-resource index.
- `https://github.com/bradtraversy/design-resources-for-developers` - broad design-resource index.
- `https://github.com/hashicorp/web-unified-docs` - current HashiCorp documentation platform reference.
- `https://github.com/339598u5uut/Course-3D` - small unlicensed and stale visual example; do not copy code or assets.

## Token and Context Efficiency

Primary:

- `https://github.com/rtk-ai/rtk` - command-output filtering and token-aware CLI proxy patterns.
- `https://github.com/tirth8205/code-review-graph` - Tree-sitter structural code graph and review navigation.
- `https://github.com/zilliztech/claude-context` - semantic code search and MCP integration.
- `https://github.com/The-PR-Agent/pr-agent` - mature provider abstraction and pull-request review workflow.
- `https://github.com/firecrawl/firecrawl` - focused web extraction and queue/API architecture; review AGPL obligations.

Experimental or limited:

- `https://github.com/mksglu/context-mode` - context sandboxing and persistence; verify license before reuse.
- `https://github.com/Mibayy/token-savior` - structural navigation; independently validate benchmark claims.
- `https://github.com/JuliusBrussee/caveman` - terse-response skill design, not general code architecture.
- `https://github.com/drona23/claude-token-efficient` - instruction-file example with limited implementation depth.

## Code Quality and Execution

Primary:

- `https://github.com/OpenHands/OpenHands` - coding-agent, sandbox, and tool-execution architecture.
- `https://github.com/n8n-io/n8n` - workflow, credentials, integrations, and queue patterns; verify fair-code license constraints.
- `https://github.com/ollama/ollama` - local model management and serving UX.
- `https://github.com/vllm-project/vllm` - high-throughput inference and OpenAI-compatible serving.
- `https://github.com/eslint/eslint` - semantic linting architecture.
- `https://github.com/prettier/prettier` - parser/printer formatting architecture.
- `https://github.com/testcontainers/testcontainers-java` - disposable integration-test environments; use language-appropriate Testcontainers package in Ecotokens.

Scale references, not templates:

- `https://github.com/kubernetes/kubernetes` - large-scale Go system; do not imitate its complexity for MVP code.
- `https://github.com/open-compress/claw-compactor` - likely Claw Compactor project; experimental and self-reported metrics.

## Skill Selection, Android, and Improvement

Primary:

- `https://github.com/android/nowinandroid` - authoritative modern Android app architecture with Kotlin and Compose.
- `https://github.com/JetBrains/kotlin` - Kotlin language internals; use Android guidance for application patterns.
- `https://github.com/google/guava` - mature Java library design.
- `https://github.com/spring-projects/spring-boot` - authoritative backend framework patterns when Java services are relevant.
- `https://github.com/stefanzweifel/git-auto-commit-action` - GitHub Actions commit automation; pin releases and minimize token permissions.
- `https://github.com/oss-review-toolkit/ort` - dependency, license, policy, vulnerability, and SBOM workflows.

Existing installed skills should be preferred for skill routing, Android, testing, refactoring, and design work. Use the OpenCode skill registry instead of inventing a remote skill selector.
