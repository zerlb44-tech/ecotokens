# Ecotokens MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a locally runnable BYOK coding orchestrator that first completes a fixture-repository workflow with mock providers, then supports real FreeModel, OpenAI, Groq, Gemini, and GitHub App integrations while enforcing sandbox, budget, cancellation, and draft-PR safety gates.

**Architecture:** Use a pnpm TypeScript workspace with a Next.js App Router application, focused domain packages, PostgreSQL/Drizzle persistence, and Redis/BullMQ durable jobs. The deterministic orchestrator owns state, role assignment, budgets, patch application, and stop decisions; provider, sandbox, policy, and GitHub capabilities are narrow injected ports so the same workflow runs against local mocks first and real adapters second.

**Tech Stack:** Node.js 22 LTS, pnpm 10, TypeScript 5.x strict mode, Next.js 16 App Router, React 19, PostgreSQL 17, Drizzle ORM/Kit, Redis 7, BullMQ, Zod 4, Vitest, Playwright, Octokit, OpenAI SDK, Google Gen AI SDK, Anthropic-compatible HTTP, Docker Engine API via `dockerode`, Web Crypto/Node crypto, Server-Sent Events.

## Global Constraints

- This is a new project; do not add compatibility layers or production deployment configuration.
- Use `pnpm` workspaces and one lockfile; require Node.js `>=22.0.0` and pnpm `>=10.0.0`.
- TypeScript uses `strict`, `noUncheckedIndexedAccess`, and `exactOptionalPropertyTypes`; source files stay focused and domain-named.
- Maximum model calls per orchestrator run: `8`.
- Maximum correction cycles: `2`.
- Maximum concurrent paid calls: `2`.
- Maximum retries per transiently failed step: `2`, with jittered exponential backoff.
- Experimental Team mode maximum agent messages: `12`; maximum agent steps: `6`; maximum correction cycles: `2`; maximum concurrent paid calls: `2`.
- User-defined maximum token and monetary budgets are mandatory; warn at `80 percent` and reject new calls at `100 percent`.
- Retry timeout, connection reset, HTTP `429`, and selected `5xx`; never retry `400`, `401`, `403`, policy rejection, validation failure, or context overflow.
- Every model step and durable workflow action has an idempotency key; hidden provider SDK retries are disabled where possible.
- FreeModel is primary whenever a suitable candidate exists; fallback is allowed only for exhausted model quota, exhausted bounded `429` retries, model removal/unavailability, or remaining-budget incompatibility.
- FreeModel fallback never applies to invalid credentials, malformed requests, policy rejection, unsafe output, or incompatible context size.
- No agent applies patches, invokes another agent, changes limits, or mutates workflow state; all agent output is Zod-validated data interpreted by the orchestrator.
- Every run is pinned to a base commit SHA and uses branch `ecotokens/<run-id>`; never write to, force-push, or merge the base branch.
- All repository commands execute in an ephemeral sandbox with fixed CPU, memory, disk, process, output, and wall-clock limits; network is disabled after dependency preparation.
- No model credential enters a sandbox or GitHub operation; no GitHub credential enters a provider call; source trees are not persisted in PostgreSQL.
- Provider credentials use envelope encryption with per-user/per-provider encryption context, are decrypted only in provider workers for one request, and are never returned to the browser.
- Immediate stop conditions are detected secrets, protected-path access, forbidden sandbox commands, budget exhaustion, explicit cancellation, and confirmed repository-integrity violations.
- Draft PR creation requires policy scans and configured verification gates; failed checks produce no ready PR unless the user explicitly requests a draft containing known failures.
- Missing providers degrade role coverage rather than block a run when another connected model satisfies the role policy; all substitutions and skipped independent checks are disclosed.
- The first release gate is a complete local mock-provider fixture flow; real provider and GitHub tasks begin only after that gate passes.
- Use non-interactive commands and commits only; never initialize Git as part of this plan.
