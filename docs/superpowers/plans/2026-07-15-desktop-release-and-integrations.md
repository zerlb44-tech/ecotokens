# Ecotokens Desktop Release and Integrations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the current mock-first web MVP into a downloadable, secure desktop application for Windows, macOS, and Linux, while establishing stable extension points for Claude Code, Codex, OpenCode, real BYOK providers, GitHub App operations, and future integrations.

**Architecture:** Keep TypeScript as the product language and package the application with Electron rather than rewriting the orchestrator in Rust. A sandboxed renderer uses a narrow Zod-validated preload bridge; the Electron main process owns filesystem, process, credential, GitHub, provider, and update capabilities. Shared domain packages remain independent from Electron so a hosted web service or a future Tauri shell can reuse the same contracts.

**Tech Stack:** Node.js 22+, TypeScript 5.9 strict mode, React 19, Next.js static export for the renderer, Electron, Electron Builder, Vitest, Playwright Electron, Zod 4, `keytar` or Electron `safeStorage`, Octokit, provider HTTP adapters, GitHub Actions, CodeQL, CycloneDX SBOM, SHA-256 checksums, GitHub Releases.

## Product Direction

The interface takes complementary product ideas without visually cloning another product:

- **Claude Code:** persistent project context, visible plan, explicit permission prompts, and continuity between sessions.
- **Codex:** task-first execution, diff-centric review, queued work, clear approvals, and evidence before completion.
- **OpenCode:** open provider/model selection, visible tools and skills, protocol flexibility, and local-first operation.
- **Ecotokens identity:** measured token/cost savings, deterministic orchestration, independent verification coverage, and human-owned draft pull requests.

The default desktop layout is a three-zone workspace:

1. Left rail: projects, branches, sessions, providers, and installed CLI adapters.
2. Center workspace: task composer, plan, agent timeline, terminal summaries, and diff review.
3. Right inspector: token/cost budget, model substitutions, verification coverage, permissions, and release evidence.

Do not reproduce Claude, Codex, or OpenCode logos, proprietary copy, exact layouts, or closed-source behavior. Their names appear only where users configure legitimate local integrations.

## Global Constraints

- Preserve all invariants in `docs/superpowers/specs/2026-07-15-ecotokens-mvp-design.md`.
- FreeModel remains primary when a suitable configured model is available.
- `70%` remains a measured target against a declared baseline, never an unconditional marketing guarantee.
- Renderer uses `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, no Electron `remote`, and a strict Content Security Policy.
- Renderer cannot access filesystem, child processes, API keys, GitHub tokens, or arbitrary IPC channels directly.
- Every IPC request and response is Zod-validated on both sides.
- CLI processes run with `shell: false`, explicit executable/arguments, bounded output, timeout, cancellation, workspace root, and a minimal environment.
- Do not pass stored provider keys to Claude Code, Codex, OpenCode, repository commands, or model prompts unless the user explicitly configures that integration to own the key.
- Never auto-merge, force-push, deploy, publish packages, or run arbitrary shell text generated by a model.
- Desktop application writes only to an app-owned data directory and user-selected repository workspaces.
- Production installers must be reproducible from a tag and include checksums, SBOM, release notes, and provenance.
- Windows and macOS stable artifacts require code signing. Unsigned artifacts are allowed only on clearly labeled development or prerelease channels.
- Release jobs receive signing secrets only on protected version tags and never on pull requests.
- Keep the current browser mock mode working until the desktop acceptance gate replaces it.
- Use TDD for behavior changes and run focused tests before the full release matrix.

## Release Artifacts

| Platform | Architecture | Stable artifact | Additional artifact |
| --- | --- | --- | --- |
| Windows | x64 | NSIS installer `.exe` | portable `.zip` |
| macOS | arm64 | signed/notarized `.dmg` | `.zip` |
| macOS | x64 | signed/notarized `.dmg` | `.zip` |
| Linux | x64 | `.AppImage` | `.deb` and `.tar.gz` |

Each GitHub Release also contains `SHA256SUMS.txt`, `sbom.cdx.json`, release notes, and provenance/attestation metadata. A release is not marked stable if any required platform artifact, signature, smoke test, checksum, or SBOM is missing.
